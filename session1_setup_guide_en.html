Session 1 · Setup Step-by-Step Guide ~ 30–45 min

Connect Your Bot
to Facebook

From zero to a Facebook-verified webhook — in exactly 8 steps: create the App, get a token, open ngrok, and configure the webhook.

What you'll achieve

By the end, Facebook will be able to reach the server running on your machine: every message a customer sends on your fanpage travels through ngrok → into your FastAPI app, and the bot replies back. This is the hardest infrastructure part of Session 1 — go slow, get it solid.

This guide covers the setup outside the code. The code (config.py, webhook.py, messenger.py) is already in the project — here we only wire up Facebook and the network plumbing.

Step 0 — Python environment

do this first

Before any Facebook work, get the project installing cleanly. The Session 1 starter needs only four small packages, so it installs fast. Still, use Python 3.11 or 3.12 for the whole course: the heavier libraries added later (e.g. numpy via pinecone) have no prebuilt wheel on 3.13 / 3.14, so pip would try to compile them and fail with a compiler error.

0
Virtual environment & pip install
Use Python 3.11/3.12 in an isolated .venv, then install
~ 8 min

1 · Check which Python you have

py -0p

Look for a 3.11 or 3.12 line. If you only see 3.13 / 3.14, install 3.12 first, then reopen the terminal:

winget install Python.Python.3.12
# or download a 3.12.x installer from python.org/downloads

2 · Create & activate the venv (inside the project folder)

py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python --version          # must print 3.12.x (or 3.11.x)
If activation is blocked

PowerShell may refuse with "running scripts is disabled". Allow it for this terminal only, then activate again:

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

When the venv is active, your prompt starts with (.venv).

3 · Upgrade pip, then install

python -m pip install --upgrade pip
pip install -r requirements.txt
Error: "NumPy requires GCC >= 8.4" / building numpy from source

You're on Python 3.13 / 3.14 — there's no prebuilt numpy for it, so pip tries to compile it and fails. Fix: recreate the venv with 3.12.

deactivate
Remove-Item -Recurse -Force .venv
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Stuck on endless "Downloading" of many versions?

That's pip backtracking through dependency versions. Upgrading pip (step 3) usually fixes it. If it still hangs for several minutes, press Ctrl+C and run the install again after the upgrade.

Verify

The install ends with Successfully installed ..., and this prints OK:

python -c "import fastapi, uvicorn, langchain, httpx, pydantic_settings, numpy; print('OK', numpy.__version__)"
Every new terminal: activate first

Each time you open a fresh terminal to run the bot, activate the venv before anything else — otherwise Windows falls back to the wrong Python and the errors return:

.\.venv\Scripts\Activate.ps1

The steps — do them in order

8 steps

Each step has a What to do list, an illustrative figure, optional Hint / Watch out boxes, and a Verify box so you can confirm you're correct before moving on.

01
Create a test fanpage
Your own Facebook page to try the bot on
~ 3 min

What to do

  1. Go to facebook.com/pages/create → choose a page type (e.g. "Local business").
  2. Name it, for example "Pet Salon Test – [Your Name]", then create it.
  3. Make sure you are an admin of this page (the creator is admin by default).
Watch out — Development mode

A new Facebook App is in Development mode: the bot only replies to admins of that page. So each student must use their own test page. You can't use a client's real fanpage without Meta App Review (1–2 weeks).

Verify

You can open the new page and see "Admin" listed for your account.

02
Create the App + add Messenger
The App is the bridge between your code and Facebook
~ 5 min

What to do

  1. Go to developers.facebook.com → My Apps → Create App.
  2. App details: give the app a name (e.g. "MyPetStore") and your contact email → Next.
  3. Use cases: filter by "Business messaging" and select "Engage with customers on Messenger from Meta" → Next.
  4. Step through Business → Requirements → Overview (you can skip connecting a Business portfolio for now) → Create app.
Hint — Meta's UI shifts

Meta changes this flow fairly often. If a label isn't where described, search by keyword: "Messenger", "Use cases", "Generate access tokens". The logic of the steps doesn't change.

"Unpublished" is normal

Your new app shows Unpublished (Development mode) in the sidebar — that is exactly what you want. In Development mode the bot works on your own page for anyone with an app role; you do not need to publish it. Going Live needs Meta App Review (out of scope).

Verify

The app dashboard opens, the sidebar shows Use cases, and the status reads Unpublished.

03
Get the Page Access Token
The key your code uses to send messages as the page
~ 4 min

What to do

Heads-up: the Page Access Token is not the App secret in App settings → Basic — those are different things. Don't use the App secret here.

  1. In the left sidebar click Use cases → on the Messenger use case click Customize.
  2. In the sub-menu click Messenger API Settings.
  3. Scroll to "2. Generate access tokens" → click Add Page / Connect → choose your test page → grant permissions.
  4. Click Generate in the Token column → copy the long EAA… string from the popup. This is your FB_PAGE_ACCESS_TOKEN.
App secret ≠ Page Access Token

In App settings → Basic you'll see App ID and App secret — ignore them for this project. The App secret is only for optional webhook signature verification (out of scope). The key you need is generated under Messenger API Settings.

Watch out — keep the token secret

This token lets anyone send messages as your page. Never paste it into code, public chat, or git. Keep it only in .env (which .gitignore already excludes). The popup closes once you copy — re-click Generate if you lose it.

Verify

You have a long token starting with EAA… copied. In the table the page row shows "Token generated".

04
Extend the token to 60 days
Check the expiry in the debugger — extend only if needed
~ 4 min

What to do

  1. Open the Access Token Debugger: developers.facebook.com/tools/debug/accesstoken.
  2. Paste the token → click Debug. Confirm Type: Page and that Scopes include pages_messaging.
  3. Read the "Expires" line:
    • "Never" (common for the Messenger-panel token) → nothing to do, use it as-is.
    • "in about an hour" → click "Extend Access Token" at the bottom and copy the new long-lived token.
Don't confuse the two "expires"

Expires is the token's validity — you want "Never" or ~60 days. Data Access Expires (~3 months) is a separate user-data permission window and does not stop your token from working. Ignore it for this project.

Pitfall #3 — token expiry

If you ever get a 1-hour token and skip extending, the bot "suddenly" stops replying mid-class. So if a working bot goes silent, suspect an expired token first. Extending is not automatic (out of scope) — redo this step when it expires.

Verify

The debugger shows Valid: True and Expires: Never (or ≈ 60 days after extending).

05
Fill in the .env file
Set the token + verify token so the server can handshake
~ 3 min

What to do

First create your .env from the template (only once):

Copy-Item .env.example .env

Then open .env and fill in the two Facebook lines. FB_VERIFY_TOKEN is a string you make up (anything) — it must match what you enter in Meta at Step 07.

Hint — what is FB_VERIFY_TOKEN?

It is not your Facebook password. It's just a "handshake password" you invent, so Facebook and your server can prove they're a matching pair. Any value works, as long as both sides are identical.

Verify

.env has real values for both FB_VERIFY_TOKEN and FB_PAGE_ACCESS_TOKEN (no longer blank).

06
Run the server + ngrok
Create a public HTTPS URL that points to your machine
~ 10 min

Why ngrok?

Your server runs at localhost:8000 — only your own machine can reach it. Facebook is out on the Internet and cannot call localhost. ngrok opens a tunnel: it gives you a public HTTPS address and forwards every request straight to your machine.

Facebook  ->  https://abc.ngrok-free.app/webhook  ->  (ngrok tunnel)  ->  http://localhost:8000/webhook  ->  your app

You'll keep two terminals open side by side for the whole session.

Terminal 1 — run the server

Test it locally first: open http://localhost:8000/ → you should see {"status":"ok"}. If you get ModuleNotFoundError, your venv isn't active or the install didn't finish — go back to Step 0.

Terminal 2 — install ngrok (first time only)

ngrok now requires a free account. Sign up at dashboard.ngrok.com, then install:

# install ngrok — pick one
winget install ngrok.ngrok        # or: choco install ngrok
                                  # or download the .exe from ngrok.com/download
"ngrok is not recognized" right after installing?

winget added ngrok to your PATH, but the already-open terminal hasn't reloaded it. Either open a new PowerShell window (then re-activate the venv), or refresh PATH in the current one:

$env:Path = [System.Environment]::GetEnvironmentVariable("Path","Machine") + ";" + [System.Environment]::GetEnvironmentVariable("Path","User")

Confirm it works with ngrok version.

Terminal 2 — attach your authtoken (one time)

Copy the token from dashboard.ngrok.com → Getting Started → Your Authtoken — it's the long secret string, not the short ID (like cr_…) shown in the Authtokens list. Then run:

ngrok config add-authtoken <YOUR_AUTHTOKEN>

Terminal 2 — open the tunnel

ngrok http 8000
Error: "agent version is too old" (ERR_NGROK_121)?

winget often installs an old ngrok (e.g. 3.3.1) that your account rejects. Update it, then open the tunnel again:

ngrok update
ngrok version          # should now be 3.20 or newer
ngrok http 8000

Your saved authtoken stays — no need to re-add it.

First browser visit shows a warning page

The first time you open a *.ngrok-free.app URL in a browser, ngrok shows a grey "You are about to visit…" page → click "Visit Site". This only affects browsers; Facebook's server-to-server calls are not blocked by it.

Hint — claim a free static URL

ngrok gives each account one free static domain. Grab it from the ngrok dashboard (Domains) and run:

ngrok http --url=your-name.ngrok-free.app 8000

Benefit: the URL doesn't change on restart → you won't have to re-edit the webhook in Meta every time. Highly recommended.

Keep both terminals open

Close Terminal 1 (uvicorn) and the ngrok URL returns 502 Bad Gateway. Close Terminal 2 (ngrok) and Facebook can't reach you. Both must stay running the whole time.

Verify

ngrok shows Forwarding https://….ngrok-free.app -> http://localhost:8000. Open that URL + / in a browser (click "Visit Site" if prompted) → you see {"status":"ok"}. That means Facebook can now reach your machine.

07
Register the Webhook + verify handshake
The moment Facebook verifies your server
~ 6 min

What to do

  1. Go to Use cases → Customize → Messenger API Settings → "1. Configure webhooks".
  2. Fill in the two fields (remember to append /webhook to the URL):
  1. Click Verify and Save. Facebook immediately calls GET /webhook on your server.
What happens under the hood?

Facebook sends hub.verify_token and hub.challenge. The code in webhook.py compares the token; if it matches, it returns hub.challenge as plain text. Facebook sees the right answer → marks it verified. That's the "handshake".

If verification fails
  • The token in Meta doesn't match FB_VERIFY_TOKEN in .env (most common).
  • You forgot to append /webhook to the URL.
  • The server or ngrok isn't running, or you edited .env but didn't restart the server.
Verify

Meta shows a green "Complete / Verified" check. Your server log shows Webhook verified by Facebook.

08
Subscribe the page + pick fields
So Facebook actually pushes messages to you
~ 4 min

What to do

  1. In Messenger API Settings → "2. Generate access tokens", next to your page click Add Subscriptions.
  2. Check only the messages field (you may add messaging_postbacks if you want).
  3. Under "Subscribe to a page", choose your test fanpage → Subscribe.
Pitfall #2 — do NOT check message_echoes

If you subscribe to message_echoes, every message your bot sends comes back to the webhook → the bot replies to itself → infinite loop. Check only messages. (The code also filters is_echo as a safety net.)

Verify

Next to the page name it shows a subscribed status, and the messages field is checked.

End-to-end test & troubleshooting

echo test

Open Messenger on your phone (signed in as the page admin) and send "hello" to your test fanpage. The bot must reply "hello". In the server log you'll see the message come in and the reply go out.

If it doesn't work yet, scan this table:

SymptomCommon causeFix
Verification fails at Step 07 Token mismatch, missing /webhook, server not restarted Re-match the token, check the URL, restart uvicorn after editing .env
You message but the bot is silent Page not subscribed, or you're not a page admin Redo Step 08; message as the admin account (Dev mode)
Bot spams itself nonstop You accidentally subscribed message_echoes Uncheck message_echoes, keep only messages
Working bot suddenly goes silent Page Access Token expired (1-hour token) Extend the token (Step 04), update .env, restart
Facebook calls but log shows a send error FB_PAGE_ACCESS_TOKEN wrong/missing in .env Paste the correct token, restart the server
ngrok URL changed, webhook dead ngrok gives a random URL on each restart Use the free static domain (Hint in Step 06)
Done

Checklist before moving to the code

Before writing the AI logic in Session 2, make sure every item below passes:

  • Your .venv (Python 3.11/3.12) is active and pip install -r requirements.txt finished with no errors
  • You have your own test fanpage and you're its admin
  • You created a Facebook App with the Messenger product
  • A 60-day Page Access Token is in .env
  • FB_VERIFY_TOKEN in .env matches the one set in Meta
  • uvicorn + ngrok are running; opening the URL shows {"status":"ok"}
  • The webhook is verified (green check in Meta)
  • The page is subscribed with the messages field
  • The echo test works: send "hello" → bot replies "hello" on a real fanpage
