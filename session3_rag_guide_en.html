the Facts

From a confident bluffer to an honest expert — store your real FAQ in a vector database and let the bot look it up before answering. This is RAG.

What you'll achieve

After Session 2 your bot could talk, but it made up prices and hours. Today you give it a real knowledge base: your FAQ goes into Pinecone as searchable vectors, and a tool lets the agent retrieve the right facts before it answers — so it stops bluffing and starts quoting your actual data.

This is Retrieval-Augmented Generation (RAG): retrieve the facts, then generate a natural reply grounded in them.

Before you open this guide

You must have finished Session 2: the bot answers with the Gemini agent and remembers context. Your .env already has GOOGLE_API_KEY and LLM_PROVIDER=gemini.

CSV gotchas

03
Create the index
scripts/create_index.py — an empty vector store
~ 8 min
Concept — what is an "index"?

A Pinecone index is an empty warehouse on Pinecone's cloud that will hold your vectors. Creating it does NOT touch faqs.csv and creates no vectors yet — that's the next step. You just build the empty shelf first.

What to do — write scripts/create_index.py

"""Create the Pinecone index once (run once)."""
import os, sys
sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))

from pinecone import Pinecone, ServerlessSpec
from app.config import settings

pc = Pinecone(api_key=settings.pinecone_api_key)
name = settings.pinecone_index_name

if pc.has_index(name):
    print(f"Index '{name}' already exists.")
else:
    pc.create_index(
        name=name,
        dimension=768,          # Gemini embedding output -> 768
        metric="cosine",        # similarity measure
        spec=ServerlessSpec(cloud="aws", region="us-east-1"),  # free tier
    )
    print(f"Created index '{name}'.")

print(pc.describe_index(name))

04
Embed & upload
scripts/upload_faqs.py — fill the index (run once)
~ 12 min
Critical — the embedding model & dimension

Use models/gemini-embedding-001 (the older text-embedding-004 may return 404 Not Found on your key). It defaults to 3072 dimensions, so you MUST pass output_dimensionality=768 to match the index. Use the same setting here AND in the tool (Step 5).

What to do — write scripts/upload_faqs.py

"""Embed faqs.csv and upsert into Pinecone (run once)."""
import csv, os, sys
sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))

from langchain_google_genai import GoogleGenerativeAIEmbeddings
from pinecone import Pinecone
from app.config import settings

CSV_PATH = os.path.join(os.path.dirname(__file__), "..", "data", "faqs.csv")


def main():
    with open(CSV_PATH, encoding="utf-8") as f:
        rows = list(csv.DictReader(f))
    print(f"Loaded {len(rows)} FAQ rows.")

    embeddings = GoogleGenerativeAIEmbeddings(
        model="models/gemini-embedding-001",
        google_api_key=settings.google_api_key,
        output_dimensionality=768,
    )
    values = embeddings.embed_documents([r["question"] for r in rows])

    records = [
        {"id": f"faq-{i}", "values": vec,
         "metadata": {"question": r["question"], "answer": r["answer"]}}
        for i, (r, vec) in enumerate(zip(rows, values))
    ]

    index = Pinecone(api_key=settings.pinecone_api_key).Index(settings.pinecone_index_name)
    index.upsert(vectors=records)
    print(f"Upserted {len(records)} vectors.")
    print(index.describe_index_stats())


if __name__ == "__main__":
    main()
python scripts/upload_faqs.py
Embed question only, or question + answer?

Embedding just the question is the simple default and works well. If your answers contain searchable keywords the question lacks (e.g. "ABA Pay" only in the answer), embed question + "\n" + answer together for better recall. Metadata stays the same either way.

Verify

Prints Upserted N vectors. and total_vector_count: N (was 0 before). If you hit 429, wait a minute and re-run — upsert is idempotent.

05
Write the FAQ tool
app/tools/faq_search.py — retrieval the agent can call
~ 12 min

First make app/tools a package with an empty app/tools/__init__.py. Then write the tool:

"""FAQ retrieval tool backed by Pinecone."""
from langchain_core.tools import tool
from langchain_google_genai import GoogleGenerativeAIEmbeddings
from pinecone import Pinecone
from app.config import settings

# Build clients ONCE at import, reuse on every call.
_embeddings = GoogleGenerativeAIEmbeddings(
    model="models/gemini-embedding-001",
    google_api_key=settings.google_api_key,
    output_dimensionality=768,        # MUST match the index + upload
)
_index = Pinecone(api_key=settings.pinecone_api_key).Index(settings.pinecone_index_name)

SCORE_THRESHOLD = 0.5


@tool
def search_faq(query: str) -> str:
    """Look up the pet salon's FAQ to answer customer questions about hours,
    prices, services, location, payment, booking, and policies.
    Call this whenever the customer asks anything about the business."""
    vector = _embeddings.embed_query(query)
    result = _index.query(vector=vector, top_k=3, include_metadata=True)
    matches = [m for m in result["matches"] if m["score"] >= SCORE_THRESHOLD]
    if not matches:
        return "No relevant FAQ found. Tell the customer you'll check and follow up."
    return "\n\n".join(f"Q: {m['metadata']['question']}\nA: {m['metadata']['answer']}" for m in matches)
The docstring IS the tool's manual

The agent reads the @tool docstring to decide when to call it. Write it clearly — a vague docstring means the agent uses the tool at the wrong times.

Verify

python -c "from app.tools.faq_search import search_faq; print(search_faq.invoke('do you wash cats?'))" prints relevant Q&A. (Use .invoke() — @tool wraps the function.)

06
Wire tool + tune prompt
agent.py + prompts.py — and one critical fix
~ 10 min

1 · Attach the tool in app/agent.py

from app.tools.faq_search import search_faq
# ...
_agent = create_agent(llm, tools=[search_faq], system_prompt=SYSTEM_PROMPT)

2 · Critical fix in reply() — use .text, not .content

Once the agent has a tool, .content can be a LIST

With tool-calling, Gemini's final message .content may come back as a list of blocks, not a string. Sending that to Facebook fails with (#100) Param message[text] must be a UTF-8 encoded string. Fix: read .text (always a clean string):

# reply_text = result["messages"][-1].content   # breaks with tools
reply_text = result["messages"][-1].text   # .text concatenates text blocks

3 · Tune the prompt for natural, grounded answers (prompts.py)

SYSTEM_PROMPT = """You are a warm, friendly assistant for Happy Paws Pet Salon on Messenger.

- For ANY question about the shop, look it up in the FAQ first, then answer from it.
- Rephrase naturally and conversationally, in the SAME language the customer writes in.
  Don't copy word-for-word.
- Keep facts exact: prices, hours, numbers must match the source. Never invent them.
- If you can't find it, say you'll check with the team. NEVER make up facts.
- Never mention tools, lookups, or databases. Reply like a real staff member.
- Keep replies short and phone-friendly."""
This is where "natural" lives

What you embed controls finding the right info; how natural the reply sounds comes from the LLM + this prompt. "Rephrase naturally, same language, keep facts exact" is the sweet spot between fluent and accurate.
